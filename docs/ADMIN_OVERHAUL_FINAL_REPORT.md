## المنفذ فعلياً

1. مراجعة main والفرع القديم وPR #1 وPR #2، مع الاحتفاظ بإصلاحاتهما. الرفع تدريجي على الفرع نفسه.
2. استعادة كلمة المرور وتغييرها من جلسة Supabase متحقق منها، ورد يحمي من كشف وجود الحساب، وحدود مستقلة للطلب، ورسائل أخطاء عربية. حفظ كلمة المرور وإنهاء الجلسات نتيجتان منفصلتان.
3. إدارة وسوم مركزية تستعمل posts.tags وcms_save_post، مع دمج ذري ومراجعات وتدقيق وصلاحيات وعدد متوقع؛ لا جدول وسوم أو محرر موازٍ.
4. طابور بلاغات مستقل وقرار محفوظ؛ إخفاء/رفض التعليق مع إغلاق البلاغ والتدقيق داخل transaction واحدة.
5. ترقيم التعليقات وفلترتها على الخادم، مع تطبيق نطاق التحرير حتى على التعليقات المقبولة العامة.
6. ترتيب الصفحة الرئيسية بالسحب وبأزرار تعمل باللمس ولوحة المفاتيح، باستخدام إعدادات المنصة الحالية.
7. لون القسم وتخصص الكاتب في SQL والنماذج والعرض العام وAPI؛ تحقق يمنع ألوان CSS غير الآمنة ولا يمنح الكاتب صلاحية إدارية.
8. صفحة جلسات مستقلة لكل مشرف، دون الحاجة إلى security.manage؛ عرض جلساته فقط وإبطال الوصول الإداري لجلسة أخرى يملكها، باستخدام مخزن الإبطال القائم.
9. تحديث OpenAPI إلى 1.5.0، وإضافة تغطية SQL/API والمتصفح، والاحتفاظ بأدلة المتصفح في CI.
10. استكمال ملفات التدقيق والتصميم والمحرر والنشر وTelegram والأمان والاختبارات والتسليم، وتصحيح ملاحظات القبول القديمة عن عدم وجود مالك.

11. قرار اعتماد تحريري على إصدار review الحالي، بصلاحية النشر ونطاق المقال، متكرر بأمان دون سجل مكرر؛ تعديل المحتوى يبطل الاعتماد المشتق. يظهر في الاستوديو وقائمة وفلتر المقالات دون تغيير قيم الحالة.
12. إدارة الصفحات الثابتة بـTiptap وامتدادات مشتركة مع الاستوديو، حفظ مسودة/نشر/إلغاء نشر، صلاحيات الإعدادات وPIN للمالك وتعارض نسخ وتدقيق. القراءة العامة لا تحمل المحرر أو مسودات الصفحات أو معرف المحرر. الصفحتان الأصليتان about/privacy محفوظتان حتى نشر بديل؛ الروابط ثابتة وتدخل الصفحات المنشورة في Sitemap وMetadata.

13. توافق القراءة العامة مع المخطط السابق: إعادة الطلب دون color أو specialty فقط عند خطأ غياب العمود المحدد، مع الحفاظ على التصفية والترقيم. حفظ البيانات الجديدة يرفض صراحة إن كان المخطط غير محدث. فُتح PR #4 بعد دمج PR #3؛ لا إعادة كتابة لتاريخ الفرع.

## المعمارية والتوافق

لا مستودع أو مشروع Next.js أو قاعدة بديلة، ولا محرك نشر أو Scheduler أو محرر مكرر. بقيت حالات النشر الحالية كما هي. تمت إضافة ست migrations منذ main عند بداية العمل: الوسوم، البلاغات والتعليقات، بيانات الأقسام والكتّاب، وجلسات الحساب والاعتماد التحريري والصفحات الثابتة. اختُبرت معزولاً ولم تُطبق على الإنتاج في هذه المتابعة.

اختبارات التراجع الحالية تؤكد الحفظ المستمر، استعادة المسودات، التعارض، المكونات الأدبية، مراجعة المحتوى والنشر والوسائط والصلاحيات. تفاصيل الأعداد والاستثناءات في ADMIN_OVERHAUL_TEST_REPORT.md.

- Supabase الإنتاج: مستخدم واحد، صفر مقالات، 49 migration، أربعة Cron فعالة، وصفر جداول عامة بلا RLS. هوية المالك وPIN والبيانات محفوظة.
- فحص صحة الموقع: HTTP 200، database ready، API configured.
- Railway Telegram: Online/SUCCESS، نسخة عاملة واحدة، دون تغييرات معلقة. هذا لا يثبت دورة ربط ونشر بحساب حقيقي.
- AI معطل في الإنتاج. لا استدعاءات خارجية أو مدفوعة أُضيفت.
- إنشاء Preview يتم من المستودع والفرع الصحيحين داخل prj_wSmsdrRMlCR2zlMUTeYknVowFXHO، وليس mystron-bzgt.

## ما لم يكتمل

أُكمل قرار APPROVED المشتق وإدارة الصفحات الثابتة؛ يبقى توسيع أدوات الصفحات وترقيم قوائمها ومراجعاتها التاريخية، مع الحفظ اليدوي الحالي. يبقى أيضاً قبول WCAG بشري وفحص Android فعلي، وتوسيع دمج الوسوم لما يزيد على 500 مقال للعملية.

أكد استعلام Supabase list_branches عدم وجود فروع اختبار مستضافة حالياً. العوائق الخارجية: بيئة Staging مستضافة ومصرح بها دون أسرار إنتاجية، واستعادة كلمة المرور بالبريد فعلياً، وStorage، والدعوات، ونشر مجدول حقيقي، ودورة Telegram بحساب مصرح، وتجربة استعادة نسخة احتياطية. تبقى مراجعة تحذيرات Supabase وتبعيات التطوير موثقة في مراجعة الأمان.
