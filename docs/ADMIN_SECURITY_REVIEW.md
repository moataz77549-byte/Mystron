## نطاق التحقق

## الكتابات الجديدة

- استعادة كلمة المرور تستخدم Supabase Auth العام؛ لا إنشاء مستخدم ولا إسناد دور، ورد موحد للعناوين المعروفة والمجهولة.
- حدا طلب مستقلان للبريد وIP، وفحص Origin، ولا حفظ لكلمة المرور أو الرمز في سجلات التطبيق.
- تحديث كلمة المرور يستخدم session client والمستخدم المتحقق منه على الخادم؛ الحقول المسموحة كلمتا المرور فقط.
- يُزال إثبات PIN ويُطلب global sign-out بعد الحفظ. فشل إنهاء الجلسات يُعرض كنتيجة منفصلة دون ادعاء أن حفظ كلمة المرور فشل. إلغاء refresh token لا يجعل جميع access tokens الحالية منتهية فوراً؛ تبقى ضوابط الجلسات الإدارية القائمة ضرورية.
- الوسوم والبلاغات تتحقق من صلاحية المستخدم الحالية ونطاق المقال في SQL، وتمنع anon. اختبارات مباشرة للدوال، لا اعتماد على إخفاء القائمة.
- معالجة البلاغ والمعالجة التحريرية وسجل التدقيق transaction واحدة؛ لا تُعرض visitor_hash أو بيانات اتصال المبلغ.
- لا استدعاءات خارجية للذكاء الاصطناعي ولا تغيير لحالته في الإنتاج. تفعيل AI في harness الاختبار يخاطب مزوداً محلياً وهمياً حصراً.

## إضافات هذه الدفعة

لون القسم يقبل قيمة hex معتمة فقط، ويستخدم في حدود زخرفية. تخصص الكاتب لا يربط ملفه بهوية Auth ولا يمنحه صلاحيات.

دوال جلسات الحساب تتحقق من الهوية الحالية وتعرض جلسات auth.uid وحده، دون رموز أو IP أو User Agent. إبطال جلسة أخرى يمر بمخزن الإبطال الإداري القائم، ويمنع الاستهداف عبر الحسابات وإبطال الجلسة الحالية من هذا الزر، ويسجل التدقيق مرة واحدة.

فحص npm audit بتاريخ التقرير: صفر ثغرات في تبعيات التشغيل؛ خمس تحذيرات عالية في سلسلة أدوات التطوير التابعة لـ eslint-config-next/fast-glob/micromatch/braces، دون ثغرات حرجة. لم تُستخدم معالجة force التي تخفض إصدار إطار العمل لإخفاء النتائج.

## الاعتماد والصفحات

الاعتماد يمر بمحرك انتقال المقال القائم بصلاحية posts.publish وprivate.can_post. القرار مرتبط بالإصدار، ولا يقبل الحفظ العام حقول الاعتماد. تكرار اعتماد النسخة نفسها لا يكرر التدقيق. لم يُفرض اعتماد إلزامي يكسر مسار النشر الفوري السابق.

جدول site_pages محمي بـRLS؛ لا INSERT/UPDATE/DELETE مباشراً للأدوار العامة. كتابة RPC تتطلب settings.update وضوابط PIN الحالية للمالك. القراءة العامة تشمل المنشور فقط، ولا تمنح قراءة updated_by. SQL يتحقق من حدود الوثيقة والجذر والمفاتيح ونسخ التحديث، وAPI يتحقق من عقد Tiptap؛ يعيد العرض العام التحقق والتنقية دون ثقة بـHTML. عدم تحميل مسودة عبر الصفحة العامة مثبت في SQL والمتصفح.

التوافق مع المخطط القديم لا يتجاوز RLS أو أخطاء الصلاحية: يعاد طلب حقل العرض الاختياري فقط عند 42703/PGRST204 المطابق لاسمه. اختبارات HTTP مع Supabase client تثبت بقاء is_active/deleted_at وslug والترقيم. لا يُسقط حقل كتابة جديد بصمت.
