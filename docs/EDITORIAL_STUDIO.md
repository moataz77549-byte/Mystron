# استوديو التحرير

المحرر هو Tiptap القائم؛ لا يوجد محرر أو مشغل نشر موازٍ.

## دورة الكتابة

أنشئ مسودة، ثم حرر العنوان والملخص والمحتوى، وحدد الكاتب والقسم والصور والوسوم والمراجع. استخدم وضع التركيز أو الوضع الاحترافي دون إعادة إنشاء المستند. تُراجع المعاينة قبل الإرسال للمراجعة أو النشر.

يحفظ المستند JSON منظماً وتُشتق منه صيغة العرض والنص القابل للبحث على الخادم. تُنقّى الروابط والصور والفيديو المسموح به قبل العرض. تدعم المكونات القائمة الأبيات بشطرين والاقتباس الموثق والتنبيهات والمصادر. لا تستخدم HTML غير موثوق لتجاوز هذه المكونات.

## الحفظ والتعارض

الحفظ التلقائي متدرج ويستخدم رقم إصدار. تستمر الكتابة أثناء الطلب؛ التعديل اللاحق يدخل الحفظ التالي. نسخة المتصفح مرتبطة بالمستخدم والمقال، وتُستعاد بقرار ظاهر. فشل الشبكة لا يُعرض كنجاح. عند تعارض الإصدار تُحفظ الكتابة المحلية وتلزم مراجعة النسخة الأحدث؛ لا يوجد overwrite صامت.

الحفظ المحلي وسيلة استعادة في المتصفح نفسه وليس نسخة احتياطية مشتركة بين الأجهزة. لا تمسح بيانات المتصفح قبل تأكيد حفظ الخادم.

## الوسوم المركزية

صفحة /admin/tags تستخرج الوسوم من posts.tags الموجودة. لا تُنشئ جدول وسوم منافساً.

إعادة التسمية إلى وسم موجود تدمج التكرار، وتحافظ على ترتيب الوسوم الأخرى. التنفيذ يستدعي cms_save_post لكل مقال داخل transaction واحدة، لذلك تبقى الإصدارات والمراجعات وسجل التدقيق ومسار الفهرسة القائم. العدد المتوقع يمنع تنفيذ قائمة تغيرت منذ معاينتها. إعادة الطلب بعد اكتمال الدمج آمنة ولا تعيد إنشاء مراجعات.

التأثير محصور بالمقالات التي يملك المستخدم قراءتها وتعديلها، والنشر مطلوب لتعديل المنشور. لا تُعدّل المسودات الخاصة بغيره أو المحذوفة. الحد 500 مقال للعملية؛ الأعداد الأكبر تحتاج معالجة منفصلة.

## تحديث المتابعة — 2026-10-21

بيانات القسم والكاتب تشمل الآن اللون والتخصص في العقود والنماذج والعرض العام. لا يمنح ملف الكاتب أي صلاحية Auth. إدارة الوسوم المركزية تستخدم بنية posts.tags ودالة الحفظ الحالية للحفاظ على المراجعات والتدقيق.
