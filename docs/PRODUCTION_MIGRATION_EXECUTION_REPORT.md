## النسخ الاحتياطي وStorage

Supabase CLI المثبت هو **2.120.0**. استُعلمت مساعدات `db dump` و`db push` و`start` قبل التنفيذ.

محاولة `supabase db dump --linked --file .work/production-backup-preflight.sql` انتهت بـ`ProjectRefNotLinkedError`: لا يوجد ربط CLI محلي بالمشروع. متغيرات `SUPABASE_ACCESS_TOKEN` و`SUPABASE_DB_PASSWORD` و`DATABASE_URL` غير مهيأة في بيئة التنفيذ؛ اتصال MCP لا يهيئ اتصال CLI تلقائياً. **لم يُنتج ملف dump صالح ولم تُنفذ استعادة.** لا يُعد جرد الصفوف أو سجل الترحيلات نسخة احتياطية.

جرد Storage أكد bucket واحداً وصفر objects مسجلة في metadata وقت الفحص. لم تُجرَ نسخة ملفات أو تجربة استعادة Storage مستقلة. وفق [وثائق Supabase للنسخ الاحتياطية](https://supabase.com/docs/guides/platform/backups)، نسخة قاعدة البيانات تحفظ metadata ولا تتضمن ملفات Storage نفسها؛ لذلك لا يجوز اعتبار نجاح dump لاحقاً تحققاً تلقائياً من استعادة الملفات أو إعدادات Auth والخدمات الخارجية.

## تجربة التشغيل المحلي

أُجريت محاولة فعلية بـ`supabase start`. فشلت بـ`DockerLifecycleInspectError`: لا توجد أوامر `docker` أو `podman` ولا daemon/socket متاح. كذلك قدرات العملية `CapEff` و`CapBnd` تساوي صفراً، ومحاولة `unshare --user --map-root-user true` انتهت بـ`Operation not permitted`؛ لم ينجح بديل rootless محلي.

لم يُنشأ مشروع Supabase سحابي بديل، ولم تُستخدم قاعدة الإنتاج كبيئة اختبار مدمرة. لم تُنفذ اختبارات الإدارة والتحرير والنشر والجلسات والصفحات على نسخة Supabase محلية مستعادة؛ نتائج الحزمة المعزولة السابقة لا تحل محل هذا الشرط.

## dry-run والنشر

نُفذ `supabase db push --dry-run --linked --skip-vault`. أضيف `--skip-vault` لتجنب أي تحديث Vault خارج نطاق ترحيلات SQL. توقف الأمر بـ`ProjectRefNotLinkedError` قبل الاتصال ولم يُنتج قائمة ترحيلات CLI متحققة. لم تُستخدم `--include-all` أو `migration repair` أو `db reset --linked` لتجاوز العائق.

لم يُنفذ `db push` فعلي، ولم يُجرَ تعديل DDL/DML إنتاجي أو تغيير RLS أو حذف بيانات. لم تُدمج الشيفرة ولم يُنشر تحديث Production على Vercel `mystron`، لأن شرط نجاح قاعدة البيانات لم يتحقق. اختبارات الوظائف المنشورة بعد الترحيل لم تُنفذ.
